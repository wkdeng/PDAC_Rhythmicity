# PDAC_Rhythmicity data requirements

This is a code-only publication export.  `data/` contains directory placeholders only: do not expect an empty checkout to execute a figure notebook.  Place supplied inputs under `data/` (or point the notebook's documented `CHRONO_*_DATA_DIR` variable to a separately managed data root).  Generated source tables, figures, and logs belong in `data/publication/`, `data/figures/publication/`, and `data/logs/publication/`; they are not primary inputs and should not be versioned as a substitute for the inputs below.

## What can be regenerated

The six notebooks are self-contained **from their stated processed-input boundary**. They do not run legacy notebooks. The included workflows can generate selected RNA-seq quantifications, rMATS and DaPars2 products, but they do not make the harmonized TCGA/GTEx/CPTAC matrices, CHIRAL phases, cohort regressions, ChIP-Atlas matrices, RBP/CLIP resources, or CircadianMultiOmics (CMO) results required by the figures. Maintain an input manifest with source URL/accession, download date, checksum, genome build, and any consent/access restrictions.

## Upstream quantification workflows

`pipeline/Snakefile` starts from paired FASTQs named `<sample>_1.fastq` and `<sample>_2.fastq` in the configured `raw_dir` (default scaffold: `data/GEO_Batch1/raw`). It requires a Kallisto transcript index, STAR index, GENCODE basic GTF, hg38 3'UTR BED, chromosome-size file, and a container providing FastQC, MultiQC, Kallisto, STAR, samtools, featureCounts, rMATS, DaPars/DaPars2 and BEDTools. It writes QC, alignments/quantification, rMATS and DaPars products beneath the selected cohort data tree.

`pipeline/Snakefile_rmats.smk` starts from existing `*.bam` files in configured `bam_dir` (default scaffold: `data/GTEx/bam`) and needs indexed, compatible GRCh38 alignments plus the GTF, 3'UTR BED, chromosome-size file and DaPars2 chromosome list. It produces bedGraphs, rMATS preparation/post outputs, and `data/polyAPA/<cohort>/result_by_chromosome/` followed by aggregated `data/polyAPA/<cohort>/results/<sample>/<sample>_result_All_Prediction_Results.txt`. Configure resources/container paths and run a dry run before cluster submission.

These workflows are useful for new compatible cohorts, but **do not establish a raw-to-figure provenance chain** for all publication input files. The checked configuration was designed around GEO/GTEx-style examples; TCGA, CPTAC, CMO and supplied coverage BAMs require their own access, sample-map and processing documentation.

## External assets and provenance caveats

- **Cohorts and access:** record TCGA/GDC, GTEx, CPTAC and GEO accessions/releases and consent terms. Do not redistribute controlled BAMs, GDC protected data, or third-party reference files without confirming redistribution rights.
- **References:** the pipeline configuration names GENCODE v43 for quantification, while Figure 2 promoter work and Figure 4 coverage use GENCODE v49 GRCh38. Preserve the reference version used for each supplied product; do not silently substitute versions. ChIP-Atlas peak assignments, BioGRID/PPI inputs, TargetScan-derived burdens, Reactome, POSTAR3/eCLIP and RNAcentral/miRBase mappings are independent external inputs.
- **Identifier conventions:** processed expression/regression inputs use versionless ENSG matching in several notebooks; RBP/miRNA and PPI resources also use symbols/transcript IDs. Supply original identifier mappings and the GTF/annotation release used to create them.
- **Embedded non-data evidence:** Figure 6 driver annotations and Figure 5 curated rules are embedded in notebook code; they are code-bound reference records, not files in `data/`. The Figure 3/4 source-cache fallback tables are derived evidence that must be supplied only if raw BAM reruns are unavailable.
- **Figure 2 preparation helpers:** `run_chip_background_sensitivity.py` and `run_ppi_panel_l_background_comparison.py` can create the processed promoter-assessed and PPI background products. They require source GENCODE, ChIP-Atlas and BioGRID records; their historical comparison route also requires legacy `method_A_presence` target inputs. Figure 2 rebuilds its current target sets from the supplied all-gene regression tables, so those historical helper target tests are not the authoritative figure calculation.
- **Omitted legacy material:** included helper scripts support preparation but are not figure renderers: `aggregate_dapars_chromosome_results.py`, `build_enst_to_gene_name.py`, CHIRAL scripts, KEGG/Reactome helpers, Figure 5 RBP helpers and `kronos_cosinor.py`. Historical builders/audits are intentionally absent. EcoTyper and DaPars2 source are included with their licenses, but their models, reference data, examples, outputs and nested repositories are omitted.

## Practical intake checklist

Before running a notebook, verify that every listed file exists, its sample IDs intersect the metadata/phases in the intended order, its reference build and identifier convention match the notebook, and its checksum is recorded. Start with the notebook-specific guide in `notebook_publication/`; it provides the authoritative thresholds, optional cache behavior and coverage fallback contract. Do not fill missing inputs with generated outputs, stale caches of unknown origin, or data from another genome/reference release.
